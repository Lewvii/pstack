# Fix merge conflicts

## 触发时机

分支存在未解决的合并冲突，需要一条可靠路径回到可构建状态。

## 工作流

1. 从 git status 和冲突标记中检测出所有冲突文件。
2. 以最小且正确性优先的编辑解决每一处冲突。
3. 在安全时优先保留双方内容。否则，选择能编译、并保持公开行为稳定的那一版。
4. 用包管理器工具重新生成 lockfile，不要手工编辑。
5. 运行编译、lint 和相关测试。
6. 暂存已解决的文件，并总结关键决策。

## 约束

- 保持改动最小且可读。
- 任何文件中都不得留下冲突标记。
- 解决冲突期间避免大范围重构。
- 解决冲突期间不要 push 或打 tag。

## 输出

- 已解决的文件
- 值得注意的解决选择
- 构建与测试结果
