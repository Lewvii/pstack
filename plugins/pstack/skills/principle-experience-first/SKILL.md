# 体验优先

当实现的方便与用户的愉悦冲突时，选愉悦。

- 每一个特性、控件和选项都必须有理由
- 少上，上好（三个特性的精致体验胜过十个特性的粗糙体验）
- 先做原型再定案（设计决策放进一次性的 HTML 里比放进生产代码里便宜）
- 把细节做对（转场、对齐、间距、反馈、错误态）
- 收紧核心循环（每个特性都应当服务于主工作流，否则就该让路）

用户就是消费这份工作的人。对 UI 来说，用户是终端用户。对一个库或内部 API 来说，用户是引入它的同事。接下来维护这段代码的工程师也是用户。同样地权衡他们的体验，并从他们的角度说明影响。

基础应当服务于体验。基础思考管的是工作的*顺序*。这条原则管的是*目标*。
