# What did I get done

## 触发时机

需要一份针对特定时间范围（例如：昨天、最近 3 天或最近一周）已完成工作的简短、高信号总结。

## 工作流

1. 把请求的时间窗口换算成具体日期。
2. 读取该范围内由当前 git 用户邮箱提交的 commit。
3. 排除 merge commit 和未提交的改动。
4. 把最重要的已交付变更综合成一份简洁的状态更新。
5. 在最终总结中写明实际使用的日期范围。

## 约束

- 极其简洁，信息密度要高。
- 优先关注实质性的行为变更或架构变更。
- 省略纯外观性的改动（格式化、import、小的重命名）。
- 不要推断意图或动机。从功能上描述改动。

## 输出

- 一份适合用作状态更新的简短总结
- 实际的日期范围
- 可选：仅针对重大变更的 2 到 5 条要点
