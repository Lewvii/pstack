### Eval

**实验设计由你负责。规划、盲测、运行、综合。**

**盲测的硬性要求：**

- 候选者看到的任何目录、文件或提示词里，都不得出现 eval、test、judge、experiment、rubric、score、compare、benchmark、candidate、arena 这些词。
- 候选者的提示词看起来要像一条自然的用户请求。陈述目标，不陈述元信息。
- 不要有诱导链条的线索。不要让候选者列出它用了哪些技能、原则或文件。笼统地要设计说明，并从代码形态而非自述来评判是否遵循了链路。
- 清理目录名和 slug 名。用用户可能自己起的、像项目名的名字。
- 不要告诉候选者还存在其他候选者。
- 裁判可以知道自己正在评判，但只能通过清理后的标签看输出，绝不看模型名。
- 比较两个变体时，由一个裁判用同一把尺子、一次性给两组打分，并且不知道哪组来自哪个变体。

**步骤：**

1. **框定。** 说明被测的是哪个变体、什么行为算成功。为裁判写出评分标准（3 到 6 条具体标准）。对候选者保密。
2. **搭建清理过的环境。** 每个候选者一个工作目录，变体已就位。种上自然任务会有的上下文：项目骨架、候选者自然读到的技能。
3. **写一条自然提示词。** 用户会打出来的那种。不泄露衡量内容。
4. **并行派出 N 个候选者**，按 **arena** 技能的 Phase B 分布在不同模型上。每个在自己的清理过的目录里工作。每人拿到同样的提示词。按 Subagents 一节的要求，为每个 subagent 选择合适的推理档位。
5. **派一个盲测裁判**，按 **arena** 技能的 Phase C 选用不同的模型家族。裁判只看清理后的标签和评分标准，绝不看模型名。
6. **从转录核实链路，不靠自述。** 在 Claude Code 按项目存放转录的目录 `~/.claude/projects/<encoded-cwd>/` 下读每个候选者的本地转录。不要在 `~/.claude/projects/` 下跨目录 glob，那会越过工作区边界，读到无关项目的私密会话。看每个候选者实际打开了哪些文件。依据它真正读过的文件加上代码形态来评判是否遵循链路，绝不依据候选者自己的说法。
7. **自己从头到尾读完每个候选者的输出。** 与裁判的结论对照。不一致意味着某个模型有偏差，或者评分标准有歧义。做综合。

**回复：** 被测变体、评分标准、逐个候选者的记录、裁判结论、你的综合，以及是否应采纳该变体的建议。
