### Worktree 与模拟器清理

1. 先快照再审计。记录 `df -h /`，然后在已安装的插件下运行 `skills/poteto-mode/scripts/worktree-audit.mjs`（principle-build-the-lever）。它从 `git worktree list` 读取路径，绝不手打，因为手打的 `myrepo-worktrees/x` 会漏掉位于 `.worktrees/myrepo/x` 的那个（principle-encode-lessons-in-structure）。它按大小、年龄、合并状态、未提交工作、PR 状态和最近接触它的会话给每个 worktree 分类，然后建议归入某个桶。转录扫描很慢，放到后台。
2. 桶的建议只是建议，不是许可。被固定的会话和活跃会话才是真实产物（principle-prove-it-works）。从用户或你自己的会话列表取得这个集合，逐个交叉核对。这个杠杆曾把一个用户固定过的 worktree 标成 `safe`，所以以固定集合为准。
3. 删除前先核实使用情况。对每个 `verify-recent-chat` 行，或任何你存疑的行，扇形派出 subagent 去读转录，报告该会话是否被固定、是否仍在进行、涉及哪些 worktree（principle-guard-the-context-window，转录是大批量的）。被固定的会话会通过后台 subagent 把 arena 和 repro 工作树派到相邻 worktree 里，那些即使名字从没出现在会话列表中，也仍在使用中。按 Subagents 一节的要求，为每个 subagent 选择合适的推理档位。
4. 遇到不可逆的损失就暂停。`wip:N` 是 N 个有未提交改动的已跟踪路径，`untracked:N` 是 N 个 git 从未见过的文件。两者都有时两个都打印，形如 `wip:1,untracked:5`。`ignored:N` 是审计的 `DISPOSABLE` 列表所列构建和缓存目录之外、被 git 忽略的 N 个路径，例如 `.env` 或 `.claude/settings.local.json`，它们可能不存在于别处。用 `git -C <path> status --porcelain --ignored=matching` 列出它们。`reflog:N` 是没有任何分支、标签或远端可达、只被该 worktree 的 HEAD 及其 reflog 保留的 N 个提交，例如在 detached HEAD 上提交的工作。它们就在 `git -C <path> reflog` 打印的条目里。用 `git branch <name> <sha>` 保留任何一个。干净的工作树可以从它的分支恢复。任何一种未提交的工作，目录一删就没了，所以用审计统计时所用的那条命令把它列出来，`git -C <path> status --porcelain --untracked-files=all --ignore-submodules=none`，用 `git -C <path> diff HEAD --ignore-submodules=none --submodule=log` 展示 diff，并先取得决定。每一行状态都是处于风险中的工作，空的 diff 从不意味着没有。diff 不会包含任何未跟踪文件，而普通的 `git diff` 可能漏掉 submodule。一条 `wip` 行如果指向 submodule，代表的是它内部被修改或新增的文件，或者在那里做出的提交。在 submodule 里运行同样的 status 命令可以列出那些文件。`hold-locked` 表示另一个工具或 agent 锁住了该工作树，原因在 LOCKED 列。`git worktree remove` 会拒绝被锁的工作树，不要绕过它用 `rm -rf`。按 Autonomy 的规定，干净、已合并且未被使用的可以继续。`wip`、`untracked`、`ignored`、`reflog`、被锁定和使用中的都要暂停。
5. 清理已确认的集合。逐个路径执行 `git worktree remove --force <path>`。如果目录因被忽略的构建产物而残留，`rm -rf` 它，然后 `git worktree prune`。分支引用会保留，所以 worktree 分支上的提交得以保留。worktree 的 HEAD reflog 随之消失，只有该 reflog 可达的提交会丢失。在 submodule 内做的提交保存在 worktree 里，也随它一起走。用 `df -h /` 确认并重新列出。
6. 模拟器与其他可回收空间。模拟器通常是下一个最大的收益。`xcrun simctl --set testing delete all`（XCTestDevices 克隆）、`xcrun simctl delete unavailable`，以及 `xcrun simctl runtime list` 后对旧运行时 `runtime delete <id>`。按需还有更多：Xcode 的 `DerivedData` 和 `iOS DeviceSupport`、编辑器的 application-support 缓存、`~/.claude/shell-snapshots/` 和旧的 `~/.claude/projects/` 转录（保留 **recall** 技能和 Session pickup 会读的近期那些）、包管理器缓存（pnpm、uv、brew、yarn）。只清理用户没说要保留的缓存。

这是唯一一个会删除用户状态、却没有代码审查兜底的 playbook，所以上面的闸门就是审查。

**回复：** 前后的 `df -h /` 与回收的空间、清理掉的 worktree、以及每个被拦下的条目一行理由（被哪个会话占用，或有未提交的工作）。
