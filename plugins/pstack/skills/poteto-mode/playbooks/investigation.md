### 调查

**答案由你负责。规划、路由、撰写。**

调查类请求是只读的。它们产出有引用的解释或建议，不产出代码改动。

1. 通过 **how** 技能路由。动机类问题还要通过 **why** 技能路由。
2. 吞吐检查点保持一行：`throughput checkpoint: n/a, read-only investigation`。
3. 产出 `how` 形态的输出（Overview / Key Concepts / How It Works / Where Things Live / Gotchas），或者当请求是在几个方案之间做决定时，给出一份带取舍表的建议。
4. 对回复应用 **unslop** 技能。

不开 PR，不做 babysit，不叫 `architect`，除非这次调查在代码改动之前。如果在代码改动之前，交回用户并重新路由到 Bug fix 或 Feature。

**回复：** 调查输出。对「你确定吗」这类问题，给出你真实的判断和理由。前提错了就反驳（见 Autonomy）。
