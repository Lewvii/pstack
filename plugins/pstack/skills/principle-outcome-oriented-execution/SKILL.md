# 面向结果执行

优化的对象是预期的、可验证的终态，而不是维持平顺的中间状态。

**为什么：** 让每一个中间步骤都保持完全稳定，往往会造出临时兼容代码，而它随后会变成长期债务。向目标架构收敛，并在明确的验证边界上证明正确性。

**核心规则：**
- 终态完整性优先于过渡期稳定性
- 中间阶段出现破损是可以接受的，只要它是有计划的、有边界的、可回退的

**护栏：**
- 用于有明确阶段边界的计划性重写和迁移
- 声明哪些地方可以接受临时破损
- 迁移过程中，对正在改动的区域保留高信号的检查
- 计划完成时，要求完整的静态检查和运行时验证
